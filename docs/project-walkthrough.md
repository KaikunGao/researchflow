# ResearchFlow 项目复盘：手把手讲解

> 这份文档从要解决的问题出发，按开发阶段讲清楚 ResearchFlow 每一步做了什么、为什么这样做，
> 以及中间踩过的坑。建议通读一遍后，对照代码把每一节自己跑一遍。

---

## 0. 先想清楚要解决什么

项目起点不是技术，而是一个具体的人和一段具体的重复劳动：**券商医药组的数据分析实习生，在财报季要做的事**。

每家公司出财报那天，实习生的流程是固定的：

1. 从 Wind / Choice 导出三张报表，粘到组里的 Excel 底表里；
2. 手工把累计口径拆成单季度（Q4 = 年报 − 三季报），算同比、环比、毛利率、费用率；
3. 把数字填进点评模板："公司 2024 年实现营收 XX 亿元，同比 +XX%……"；
4. 画四张固定样式的图：营收及增速、净利润及增速、利润率、费用率。

一家公司 30 到 60 分钟，财报季一天三到五家。这四步就是四个痛点：**底表重复更新、单季度拆分易错、点评段落机械填数、标准图重复制作**。整个项目的功能都围绕它们展开：先有痛点，后有功能。

详细的用户画像和工作流写在 [intern-workflow.md](intern-workflow.md)。

## 1. 技术选型与项目骨架

**选型**

| 层 | 选择 | 为什么 |
| --- | --- | --- |
| 前端 | Next.js 16（App Router）+ TypeScript + Tailwind CSS v4 + shadcn/ui + Recharts | 现代 B2B SaaS 的标准组合；shadcn 的组件源码直接在仓库里，可以随意改样式；Recharts 对金融图表够用且是 SVG，方便导出 PNG |
| 后端 | Python 3.11+ / FastAPI / Uvicorn | 金融数据处理在 Python 生态最顺手（openpyxl、matplotlib、python-docx）；FastAPI 自带 OpenAPI 文档和 Pydantic 校验 |
| 数据库 | SQLite（标准库 `sqlite3`） | 单机工具，一个文件即可；不引入 ORM，表结构简单，手写 SQL 更透明 |
| 图表导出 | 前端 SVG → Canvas → PNG；后端 matplotlib | 前端导出不走服务器；Word 报告里的图必须服务器生成 |

**目录结构**（只列关键部分）

```
frontend/
  app/              每个路由一个目录，page.tsx 只负责包一层，逻辑都在 components/
  components/
    layout/         侧边栏、Header、AppShell
    shared/         筛选器、空状态、状态徽章、阶段提示、涨跌文本
    charts/         通用 Recharts 封装
    snapshot/ data/ overview/ analytics/ comparison/ alerts/ reports/ settings/
  hooks/            use-async（通用异步）、use-panel、use-settings、use-backend-status
  lib/              api.ts（后端客户端）、panel.ts（客户端派生计算）、chart-export.ts、format.ts
  types/api.ts      与后端 Pydantic 模型一一对应的 TS 类型
backend/app/
  api/routes/       system / datasets / companies / analytics / alerts / reports / settings / export
  core/             config（环境变量）、db（SQLite 建表）、deps（依赖注入）
  services/         所有业务逻辑，路由只做参数校验和调用
  models/schemas.py Pydantic 响应模型
```

一个贯穿始终的设计原则：**路由不写业务逻辑，业务逻辑不碰 HTTP**。`services/` 里的函数都是纯 Python，可以被路由、脚本、测试三处复用。例如 `verify_public_data.py` 脚本直接调用 `fetch_company` 和 `build_series`，不需要启动服务。

## 2. 第一阶段：先把界面骨架搭出来

第一阶段只做了七个页面的 UI 和一份统一的演示数据，后端只有 `/api/health` 和 `/api/version`。这一步的意义是**先把产品形态定下来**：左侧导航、顶部 Header、卡片式布局、深蓝品牌色、Light Mode。

两个当时就定下、后来一直沿用的规矩：

- **演示数据必须集中管理且明确标记**。所有 Mock 都在 `lib/mock/`，页面上有「演示数据」徽章；按钮点了没功能就明确提示"下一阶段开放"，不假装成功。后来接入真实数据时，直接删掉 `lib/mock/` 目录，页面组件改成从 hook 取数即可。
- **后端连接状态是真实请求的**。总览页的 Connected / Disconnected 来自实际 fetch `/api/health`，这是一个很小但能体现"不糊弄"的细节。

## 3. 第二阶段：财报速览小工具（核心）

这是项目最有价值的部分，四个痛点在这一阶段全部有了解法。

### 3.1 数据模型

SQLite 三张表（后来扩到七张）：

```sql
datasets        -- 每次导入一条：文件名、布局、行数、公司数、报告期数、警告
companies       -- code 主键、name、exchange
financial_facts -- 长表：code × period_end × field → value（亿元），UNIQUE(code, period_end, field)
```

为什么用长表而不是宽表：科目会增加，报告期会增加，长表不需要改表结构。`UNIQUE` 约束配合 `ON CONFLICT DO UPDATE`，实现"重复导入以最新为准"，并把 `dataset_id` 更新为最新来源，保留可追溯性。

### 3.2 解析器：把乱七八糟的导出表变成标准事实

文件 `services/parser.py`。核心思路是**先识别布局，再逐行映射**。

**布局识别**（扫描前 20 行）：

- 某一行里有两个以上单元格能解析成报告期（`2024-12-31`、`2024/9/30`、`20240630`、`2024年报`、`2024Q3` 都认）→ **宽表**，这一行是表头，报告期是列；
- 否则某一行里有「报告期 / 日期」列并且有至少一个能映射到标准科目的列头 → **长表**，一行一个公司-报告期；
- 两者都不是 → 跳过这个工作表并记一条警告（示例文件里的「说明」sheet 就是这样被跳过的）。

**科目映射**（`services/fields.py`）：14 个标准字段，每个字段一组别名。例如归母净利润对应「归属于母公司所有者的净利润」「归属母公司股东的净利润」「净利润(归母)」等八种写法。匹配时先去掉空格、括号内容、冒号，再按别名长度降序先精确后包含。别名长度降序是为了避免「营业总成本」被「营业成本」误匹配。

**单位换算**：优先看科目名括号里的单位，如「营业收入(万元)」；其次看表头附近的「单位：万元」；都没有则按元处理并记警告。全部统一换算为亿元存储。

**证券代码**：`600276`、`600276.SH`、`SH600276` 都归一化为 `600276.SH`；没有后缀时按首位数字推断交易所。单公司工作表（没有代码列）会从 sheet 名或标题行里找代码，比如「恒瑞医药(600276.SH) 财务摘要」。

**无法映射的科目**不会报错，而是收集起来在导入结果里提示"以下指标未能映射，已忽略"。示例文件里故意留了一个「每股收益(摊薄)」来演示这个行为。

### 3.3 指标计算：单季度拆分与口径

文件 `services/metrics.py`。口径如下：

| 项目 | 规则 |
| --- | --- |
| 累计口径 | 利润表、现金流量表的原始数据就是累计的（三季报 = 1–9 月） |
| 单季度 | Q1 = Q1 累计；Qn = Qn 累计 − Q(n−1) 累计；**缺上一期时留空，不猜** |
| 资产负债表 | 时点数，不拆分 |
| 同比 | (本期 − 上年同期) / \|上年同期\|，分母取绝对值是为了处理上年亏损的情况 |
| 环比 | 单季度与上一季度比，要求两个季度连续（Q1 的上一季度是上年 Q4） |
| 比率 | 毛利率 = (收入 − 成本) / 收入；费用率 = 费用 / 收入；累计和单季度各算一套 |
| ROE | 累计净利润 / 期末归母净资产，**摊薄口径**，界面上标注"仅作参考" |
| 周转天数 | 期末余额 / 累计成本（收入）× 报告期天数（90 / 180 / 270 / 360） |

实现上分两遍：第一遍按时间顺序算累计值、单季度和比率；第二遍回头算同比、环比和比率变化。两遍的原因是同比需要"上年同期"，第一遍跑完才能查到。

浮点细节：差分结果 `279.8 − 200.0` 在浮点下是 `79.80000000000001`，所以单季度值四舍五入到 4 位小数，解析出的原始值保留 6 位。这个坑测试里抓到过。

### 3.4 点评段落生成

文件 `services/commentary.py`。纯模板，不用大模型。四段固定结构：

1. 累计核心数据：营收、归母净利润、扣非，各带同比；
2. 盈利能力：毛利率、净利率及同比变化，四项费用率及变化；
3. 分季度：单季营收、净利润的同比和环比，单季毛利率；
4. 现金流与资产质量：经营现金流、净现比、资产负债率、周转天数。

关键设计：**缺哪个数据就略过哪个从句**，而不是输出"同比 —"。"同比 +12.3%" 和 "同比 -5.2%" 用不同措辞（增长 / 下降），比率变化说"提升 / 下降 X pct"，绝对值小于 0.05 说"基本持平"。

为什么不用大模型：数据段落要求每个数字准确、口径固定，模板的输出是确定的、可测试的；研究员要的是"把数填对"，观点部分他们自己写。

### 3.5 底表导出

文件 `services/exporter.py`，openpyxl 生成。每家公司一个 sheet，报告期横向，分九个区块：累计口径、资产负债表、单季度、累计同比、单季同比、单季环比、累计比率、单季比率、资产质量。另附「说明」sheet 写口径。这就是组里底表的形态，只是不用再手工维护。

### 3.6 前端财报速览页

`components/snapshot/`。页面结构：公司和报告期选择 → 六个 KPI → 点评卡片（一键复制）→ 四张标准图（单季 / 累计切换，各自可导出 PNG）→ 季度明细表 → 导出底表按钮。

**PNG 导出**（`lib/chart-export.ts`）是个值得讲的小技术点：

1. 找到 Recharts 渲染的 `<svg class="recharts-surface">`，克隆一份；
2. 把 `font-family` 写进每个 `<text>`，因为导出的 SVG 不再继承页面 CSS；
3. 序列化成 data URL 载入 `Image`，画到 2 倍分辨率的 Canvas 上；
4. 在 Canvas 上手工补标题、副标题、图例色块和"资料来源"一行；
5. `canvas.toBlob` 触发下载。

遇到的坑：Recharts 的图例图标也是 `recharts-surface` 类的小 SVG，`querySelector` 取到的是第一个即 14×14 的图标，导出的 PNG 只有 108 像素宽。修复是取面积最大的那个 SVG。另一个坑：速览图表的颜色不能用 CSS 变量，因为导出时 `var(--chart-1)` 无法解析，所以这几张图用固定色值。

## 4. 第三阶段：把剩下的页面全部接到真实数据

### 4.1 分析面板接口：一个接口喂三个页面

`GET /api/analytics/panel` 一次返回：公司列表（含子行业）、全部报告期、33 个指标的定义、以及 `data[code][period][metric]` 三层字典。总览、财务分析、公司对比三个页面共用这一个接口，筛选、均值、趋势、排名都在前端 `lib/panel.ts` 里算。

为什么这样而不是每个页面一个接口：数据量不大（50 家 × 30 期 × 33 指标 ≈ 5 万个数），一次拉完后切换筛选条件零延迟；而且三个页面口径必然一致，因为算法只有一份。

33 个指标来自 `services/catalog.py` 的 `flatten()`，它把 `PeriodMetrics` 展平成扁平字典，每个指标带标签、单位、分组、"越高越好"标记（排名方向用）。

子行业分类（`services/industry.py`）是一张约 50 个常见医药 A 股代码的内置对照表，未收录归「其他」。这是明确的简化，后续应允许在界面编辑。

### 4.2 告警规则引擎

表结构：`alert_rules`（名称、指标、比较符、阈值、严重度、启用）和 `alerts`（规则 × 公司 × 报告期唯一）。

评估逻辑（`services/alerts.py::evaluate`）：

1. 对每家公司取最新报告期，展平成 33 个指标；
2. 对每条启用的规则比较阈值；
3. 命中：若已有同规则同公司同报告期的告警则保持；否则先把该规则在该公司**旧报告期**的活跃告警标记为已解除（被新报告期替代），再创建新告警；
4. 未命中或规则被禁用：把该规则在该公司的活跃告警标记为已解除。

触发时机：每次导入 / 拉取后自动评估，以及页面上的"重新评估"。规则改阈值或开关后前端也会自动调用一次评估。告警状态流转：活跃 → 已确认 → 已解除，解除的可以重新激活。

默认七条规则：营收同比下滑、净利润大幅下滑（< −30%）、单季营收环比大幅下滑、毛利率跌破 25%、销售费用率高于 40%、资产负债率高于 60%、ROE 低于 5%（默认关闭，因为季度口径 ROE 意义不大）。

### 4.3 Word 报告生成

`services/reports.py`（python-docx）+ `services/charts.py`（matplotlib）。四种报告类型：

| 类型 | 内容 |
| --- | --- |
| 公司深度 | 点评段落 + 分季度数据表 + 四张标准图 + 历史指标表 |
| 同业对比 | 最新报告期对比表 + 指标排名 + 分组柱状图 + 历史表 |
| 定期跟踪 | 逐家公司：点评 + 核心表；附活跃告警 |
| 行业综述 | 板块整体与子行业均值 + 公司一览 + 增速前后五名 + 告警 |

技术要点：

- matplotlib 默认不认中文，需要设置 `font.sans-serif` 为 PingFang SC / 微软雅黑等中文字体列表，并关闭 `axes.unicode_minus`；
- Word 里的中文字体要同时设置 `rFonts` 的 `eastAsia` 属性，否则只改 `font.name` 中文仍是宋体；
- 图例会和折线顶部重叠，解决办法是把 y 轴上限抬到最大值的 1.2 到 1.3 倍给图例留白；
- 报告页眉写研究所署名和"自动生成初稿，发布前请复核"。

生成的文件存在 `backend/data/reports/`，记录存 `reports` 表，支持下载和删除。

### 4.4 设置持久化

`settings` 表是 key-value。保存的设置会真正起作用：工作区名显示在侧边栏；研究所署名和数据来源拼成图表 PNG 和 Word 报告里的"资料来源：Wind，XX证券研究所"；默认口径和图表期数影响速览页和报告里的标准图。只实现有实际用途的设置项，不做摆设。

## 5. 第四阶段：接入公开数据源

背景：找不到当年的 Wind 导出文件了。与其让解析器只针对我设计的格式，不如直接接一个公开数据源，让工具在没有 Wind 权限时也能跑真实数据。

### 5.1 数据源选择

东方财富网页端 F10 的财务报表接口（`emweb.securities.eastmoney.com/PC_HSF10/NewFinanceAnalysis/...`）。先用 akshare 试了一下，发现它会把一家公司全部历史（105 个报告期、21 次请求）都拉下来，每张表 20 到 40 秒，交互上不可接受。于是读了 akshare 的源码，直接用 `requests` 调同一个接口，先取报告期列表、按起始年份过滤、每 5 个报告期一次请求。一家公司三张表约 10 到 20 秒，依赖也从 akshare 整套减为一个 `requests`。

字段映射写在 `services/public_data.py` 的 `STATEMENTS` 里，例如 `TOTAL_OPERATE_INCOME → revenue`、`PARENT_NETPROFIT → net_profit`、`NETCASH_OPERATE → operating_cash_flow`，应收账款优先 `ACCOUNTS_RECE`，没有则退到 `NOTE_ACCOUNTS_RECE`。拉下来的数据统一转成和文件导入一样的 `ParsedFact`，后面的流程完全复用。

### 5.2 验证

`scripts/verify_public_data.py` 做了两层核对，缺一不可：

1. **与年报公告核对**：恒瑞医药 2023、2024 年度报告披露的营收、归母净利润、扣非净利润及同比共 8 项，拉取值和自算同比全部一致（2024 营收 279.85 亿、归母净利润 63.37 亿、同比 +22.63% / +47.28%）。
2. **与数据源自带同比交叉核对**：东方财富每个科目附带 `*_YOY` 字段，是它独立算的；我们用相邻年度自算的同比与之比较，2024 年报和三季报共 6 项误差小于 0.01 pct。

第二层不依赖任何人工抄录的数字，是程序对程序的交叉验证。两层一起说明"数据拿对了，口径算对了"。

### 5.3 测试策略

- 单元测试用一个伪造的 `Session` 模拟接口响应，覆盖字段映射、年份过滤、空值回退、分页请求次数；
- 接口端到端测试用 `monkeypatch` 把 `requests.Session` 换成伪造的，不碰网络；
- 真正访问网络的测试用环境变量 `RESEARCHFLOW_LIVE_TESTS=1` 才开启，默认跳过，保证 CI 稳定。

## 7. 踩过的坑

1. **PNG 导出选错 SVG**：Recharts 图例图标也带 `recharts-surface` 类，导出成了 108 像素的小图。改为取面积最大的 SVG。
2. **CSS 变量在导出时失效**：页面图表用 `var(--chart-1)`，导出的 SVG 脱离页面后颜色丢失。速览图表改用固定色值。
3. **浮点差分尾数**：`279.8 − 200.0 = 79.80000000000001`，测试断言失败。统一四舍五入。
4. **单公司表的公司名提取**：从「恒瑞医药(600276.SH) 财务摘要」里提取名称时把整句都当成了名字，改为取代码前的那一段。
5. **示例数据太平稳触发不了告警**：给两家公司加了 2024 年业绩下滑场景，既贴近真实（集采、需求放缓），又能演示规则引擎。
6. **akshare 太慢**：全量历史 21 次请求。读源码后直接调接口并按年份过滤。
7. **React 编译器的 lint 规则**：`useEffect` 里同步 `setState` 会报错。把"用加载到的数据初始化本地状态"改为派生值（例如 `effectivePeriod = period || latest`），既过 lint，代码也更简单。
8. **Base UI 的 Select 在自动化点击下不展开**：实际是测试工具的问题，用 JS 派发事件验证组件本身正常。教训：先确认是组件问题还是工具问题。
9. **matplotlib 中文**：方框乱码，设置字体列表；负号显示成方框，关 `unicode_minus`。
10. **Word 中文字体**：只设 `font.name` 不够，必须设 `eastAsia`。
