## 1. 产品背景

证券公司行业研究员的日常工作中，大量时间消耗在**非研究性的重复劳动**上：

- 从 Wind / Choice / 巨潮资讯等渠道导出上市公司三大报表，手动整理到 Excel；
- 反复计算营收增速、毛利率、净利率、ROE、研发费用率等常用指标；
- 为每一篇报告重新绘制同类型的趋势图、对比图；
- 在年报 / 季报密集发布期，人工逐家核对关键指标是否出现异常；
- 将数据、图表、文字粘贴进研究报告模板。

这些工作流程高度标准化，却缺少一个面向研究员工作流的轻量工具。ResearchFlow 希望成为研究员的“财务数据工作台”，把数据整理、计算、可视化与报告初稿生成自动化，让研究员把时间花在判断与观点上。

第一版聚焦 **A 股医药生物行业**：该行业公司数量多、子行业分化明显（化学制药、生物制品、医疗器械、中药、医疗服务 / CXO），对横向对比与异常监控的需求突出，适合作为验证场景。

## 2. 目标用户

| 用户角色 | 典型场景 | 核心诉求 |
| --- | --- | --- |
| 证券公司行业研究员（核心用户） | 覆盖 10–30 家公司，季度 / 年度更新财务跟踪 | 快速更新数据、一键出图、第一时间发现异常 |
| 金融数据分析师 | 为研究团队维护数据底表与指标口径 | 数据标准化、口径统一、可追溯 |
| 研究助理 / 实习生 | 协助整理数据与制作报告图表 | 降低操作门槛、减少手工错误 |

## 3. 业务痛点

> 更贴近实习生日常工作的详细流程与痛点整理见 [intern-workflow.md](intern-workflow.md)。

1. **数据整理耗时**：不同来源导出的字段名、单位（元 / 万元 / 亿元）、报告期格式不一致，需要手工清洗。
2. **指标计算重复**：每次更新都要重算同一批指标，Excel 公式易出错且难以复用。
3. **可视化重复劳动**：趋势图、对比图样式固定，但每篇报告都要重新制作。
4. **异常发现滞后**：财报密集发布期靠人工逐家查看，容易遗漏关键指标的异常变化。
5. **报告制作机械**：报告中的数据段落、图表、表格高度模板化，但仍需人工拼装。
6. **口径不统一**：团队内不同成员对同一指标的计算口径不一致，影响横向对比。

## 4. 未来核心功能

| # | 功能 | 说明 |
| --- | --- | --- |
| 1 | Excel / CSV 财务数据导入 | 支持拖拽上传，识别常见数据源的导出格式 |
| 2 | 自动数据清洗和标准化 | 字段映射、单位统一、报告期规范化、缺失值与重复值处理、质量校验 |
| 3 | 财务指标计算 | 增速、盈利能力、运营效率、偿债能力、现金流等指标的统一口径计算 |
| 4 | 上市公司财务分析 Dashboard | 行业 KPI、趋势图、行业表现、公司概览 |
| 5 | 多家公司财务对比 | 2–10 家公司在任意指标上的横向对比图表与表格 |
| 6 | 关键财务指标异常监控 | 基于规则的阈值告警、告警历史、规则管理 |
| 7 | 自动化行业研究报告生成 | 按报告类型、公司、报告期、指标自动生成报告初稿（图表 + 表格 + 数据描述） |

## 5. MVP 范围（当前代码状态：Phase 1 – Phase 4）

Phase 1 搭建了**可运行、可导航、可演示**的产品骨架；Phase 2 在此基础上交付了第一个真正可用的小工具「财报速览」，针对实习生最高频的四个痛点（详见 [intern-workflow.md](intern-workflow.md)）。

### 5.0 Phase 4 已完成：公开数据源接入与口径验证

| 模块 | 交付 |
| --- | --- |
| 公开数据拉取 | `POST /api/datasets/fetch`：按证券代码从东方财富 F10 拉取利润表、资产负债表、现金流量表（按报告期、累计口径），按起始年份过滤后分页请求，每家公司约 5–15 秒；数据管理页新增「从公开数据源拉取」入口 |
| 口径验证 | `scripts/verify_public_data.py`：恒瑞医药 2023 / 2024 年报公告披露的营收、归母净利润、扣非净利润、同比共 8 项全部一致；自算同比与东方财富自带同比字段 6 项一致；单季度拆分抽查 |
| 测试 | 用伪造接口响应的单元测试覆盖字段映射、年份过滤、空值回退与接口端到端；真实网络测试通过环境变量 `RESEARCHFLOW_LIVE_TESTS=1` 启用 |

意义：工具不再依赖 Wind 权限即可用真实财务数据运行；作品集中的数字可对照公告核验。

### 5.0.0 Phase 3 已完成：全部页面接入真实数据

| 模块 | 交付 |
| --- | --- |
| 分析面板 | `GET /api/analytics/panel` 一次返回全部公司 × 报告期 × 33 个指标（规模、单季度、成长、盈利、费用、变化、资产质量），前端在 `lib/panel.ts` 做筛选、均值、趋势、排名；总览 / 财务分析 / 公司对比三页共用 |
| 子行业分类 | 内置约 50 个医药 A 股代码的子行业对照表，总览按子行业聚合，未收录归「其他」 |
| 异常监控 | 规则引擎：规则存 SQLite，默认 7 条，可增删改与调阈值；导入后与手动「重新评估」时对各公司最新报告期评估；告警状态活跃 → 已确认 → 已解除，旧报告期告警在新报告期触发时自动解除 |
| 报告生成 | python-docx + matplotlib 生成 Word 初稿，四种类型：公司深度（点评 + 分季表 + 四图 + 历史表）、同业对比（对比表 + 排名 + 对比图 + 历史表）、定期跟踪（逐家点评 + 核心表 + 告警）、行业综述（整体与子行业均值 + 公司一览 + 增速前后五名 + 告警）；文件保存在 `backend/data/reports/` |
| 设置 | 工作区名、研究所署名、数据来源、默认口径、图表期数持久化到 SQLite；作用于侧边栏、PNG 导出的资料来源、报告页眉与报告图表 |
| 清理 | 删除全部前端演示数据（`lib/mock`），各页面在无数据时显示空状态并提供示例导入入口 |

### 5.0.1 Phase 2 已完成：财报速览小工具

### 5.1 Phase 1 已完成

- 前后端分离的项目结构（Next.js + FastAPI）。

- 左侧固定导航 + 顶部 Header + 主内容区；移动端为抽屉式导航。
- 七个页面全部可导航：

  - **数据管理**：拖拽上传区域、Import Data 按钮（点击提示“下一阶段开放”）、数据集状态统计、最近数据集表格。
  - **财务分析**：财务指标选择器、子行业筛选、起止报告期筛选、趋势图、公司表现排名、财务数据表格。
  - **公司对比**：按子行业分组的公司多选（2–10 家）、指标选择器、柱状 / 折线切换的对比图、对比表格。
  - **异常监控**：告警汇总卡片、活跃告警、告警规则（只读）、历史记录。
  - **报告生成**：报告类型、公司选择、报告期、包含指标、Generate Report 按钮（点击提示“后续阶段开放”）、已生成报告列表。
  - **设置**：通用设置、数据偏好、显示偏好（仅 UI，不持久化）。
- 统一的演示数据源（`frontend/lib/mock/`）：公司、财务记录、告警、数据集、报告；KPI / 图表 / 表格均由同一份数据派生，筛选条件变化时联动更新。
- 后端接口：`GET /api/health`、`GET /api/version`，已配置 CORS 允许本地前端访问；pytest 覆盖两个接口与 CORS 头。
- 总览页的后端连接状态组件实际请求 `/api/health`，真实显示 Connected / Disconnected。

### 后续阶段需要特别注意的事项

1. **数据源格式差异**：Wind、Choice、巨潮资讯导出的列名、单位与报告期写法不同，需要可配置的字段映射规则，而非硬编码。
2. **单位与口径**：金额统一为亿元、比率统一为百分比；同一指标（如 ROE 的加权 / 摊薄口径）需明确定义并在界面上标注。
3. **报告期模型**：前后端已统一为季度报告期（`YYYY-MM-DD`），新增年度口径聚合（如年化 ROE）时需在 `services/metrics.py` 集中实现。
4. **数据质量校验**：缺失报告期、重复记录、异常值（如营收为负）需在导入阶段给出可读的错误信息，并保留在数据集状态中。
5. **可追溯性**：每条财务记录应记录来源数据集与导入时间，便于后续核对与回滚。
6. **接口契约**：前端 `types/index.ts` 已定义 `Company`、`FinancialRecord`、`Dataset` 等类型，后端 Pydantic 模型应与之对齐，避免前后端各自定义口径。
7. **数据派生放在 `lib/panel.ts`**：页面组件不要各自计算均值 / 增速，统一走 `lib/panel.ts` 与后端 `services/catalog.py`，保证口径一致。
8. **真实样例校准**：解析器的别名表与布局识别基于典型 Wind / Choice 格式，拿到实习时的真实导出文件后应先补充测试用例再调整。
